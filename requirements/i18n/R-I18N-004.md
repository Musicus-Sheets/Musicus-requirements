# R-I18N-004 Errors as codes, no text from the server

## Statement

The server shall send no text meant for users in error responses and import results: every error, every reason why a piece was not imported, why a staged import file was skipped or rejected, and every import note shall be a stable code with typed arguments (numbers, field names, the user's own data such as a path or a title). An error response may carry an English `message` for API users and logs; the web client shall not show it, except for a code it does not know (a newer server). The client shall have a text for every code.

## Rationale

Only the client knows the user's language (F-I18N-001). A sentence built on the server would always be English, and a server that sends codes can be used by other clients (a future app) with their own texts.

## Acceptance criteria

- A password that is too short is answered with HTTP 400 and `{"error": "bad_request", "code": "password_too_short", "args": {"min": 8}, "message": "the password needs at least 8 characters"}`.
- A commit that refuses a piece names the blocking import note as data (`import_blocked` with the note's kind and detail), not as a sentence.
- A file of an import batch that is already in the library is marked with the code `duplicate_in_library` and the title of the piece.
- Adding a code without a client text does not compile.
